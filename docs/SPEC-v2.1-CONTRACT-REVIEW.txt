二、Plain Text-B — 文件原文保真契约
--------------------------------------------
PT-01 [PROPOSED] .txt/.md/.json 和批准的源码类型以原始纯文本预览；
  .docx/.pdf/图片/视频只读，不得将 DOCX 提取的文字假装写回原始 DOCX。
PT-02 [PROPOSED] HTML/Markdown/代码均按字面显示，不渲染/执行文件中的
  <script>、<img onerror=...>、JS 代码和 Markdown 标记。
PT-03 [PROPOSED] 预览保留文本行序、空行、前导/尾随空格、Tab 和末尾换行语义；
  等宽字体，长行可滚动；显示层自动换行不得影响保存字节。
PT-04 [PROPOSED] UTF-8 默认，原有 UTF-8 BOM 必须保存；
  原有 CRLF/LF 编辑后保持其行尾惯例。不能让 textarea/contenteditable
  自动将 CRLF 静默规范化为 LF 后写回。
PT-05 [PROPOSED] 混合 LF/CRLF、非法 UTF-8、未知编码和二进制 NUL：
  未实现无损编辑机制前只读并明确警告。UTF-16 支持不在当前基础承诺中。
PT-06 [PROPOSED] 打开并退出而不点击保存，原始字节 SHA-256、长度和版本数都不变。
  即使点击保存的文本与之前相同，写出的内容 SHA-256 仍需一致；
  按 v2 §7“每次保存形成新版本”，显式保存暂定版本 +1（需决策）。
  字节一致和版本计数是不同断言。
PT-07 [CODE] 旧 Node editor.js:77–79 使用 innerText + text/plain 保存；
  富文本按钮加粗、颜色、字号不会被保存。
  新版 Plain Text 模式不得显示会误导用户的不可持久化 Ribbon；
  如保留 C10 真富文本必须定义载体、格式、清洗、回放和相应测试。
PT-08 [PROPOSED] 保存在 service 层复验 modify、锁主/令牌、锁有效期、
  base_version；版本冲突 409，不能覆盖他人的更新。
PT-09 [CODE] 旧 Node preview.js:39 对正文 slice(0,2000000) 静默截断；
  新版超限必须返回 truncated、实际返回量、原始大小、可用下载。
PT-10 [PROPOSED] 内容渲染必须使用安全文本节点；搜索高亮以安全文本片段+
  mark 节点生成；DOCX 输出 HTML 需清洗；不可信 HTML/SVG raw 需要
  MIME、nosniff、CSP/隔离策略，禁止同源脚本执行。
PT-11 [PROPOSED] 文件大小限制须同时计入 dataURL 的 base64 膨胀；
  150MB JSON 请求限制不代表支持 150MB 原始文件。
PT-12 [PROPOSED] 纯文本内容可以包含 Unicode、中文、emoji、尖括号、
  引号和控制文本；UI 禁 emoji 图标不限制文件本身。
PT-13 [PROPOSED] raw/preview/download 之间明确权限差别；
  不能让仅有 preview 权限的用户绕过 download 限制。
PT-14 [PROPOSED] 审批修改、非审批保存、回滚后下载的 SHA-256、
  预览正文、索引文本和最新版本记录必须保持一致。

固定夹具和可测结果：
 TB01 UTF-8/LF，空行、Tab、连续空格、末尾 LF：读/写字节一致。
 TB02 UTF-8/CRLF，中文、英文和 BOM 变体：编辑后行尾、BOM 不丢失。
 TB03 混合行尾：若未支持无损编辑，明确只读和原因。
 TB04 非法 UTF-8 / NUL：不得替换坏字节后写回。
 TB05 文本含 <script>alert(1)</script>、HTML onerror：展示字面量、不执行。
 TB06 Markdown 语法原文保留，不自动转富文本。
 TB07 超长单行、Tab、结尾空格：显示可读、下载 checksum 不变。
 TB08 大于预览阈值：明确截断标识和下载。
 TB09 A/B 并发打开；A 保存后 B 旧版本保存获 409，不覆盖。
 TB10 预览、直接保存、审批通过、回滚后核对下载 checksum 与版本数。
 TB11 只打开不保存：版本与 checksum 零变化。
 TB12 内容相同但点击保存：字节相同，版本行为符合用户最终裁决。
每例应记录：原始 checksum、编码/BOM/EOL、登录身份、文件和目录权限、
操作、HTTP 码、UI 显示、下载 checksum、版本序列。仅截图一致不算通过。

三、P0 缺口：权限、锁、版本、审批
--------------------------------------------
SEC-01 [CODE] app.js ACL 新增/读取/撤销只要求 requireAuth；
  v2 API 表继续标为“会话”。不能照搬此越权漏洞。
  默认 admin 管 ACL；普通用户要另有明确的 manage_acl 授权才允许；
  此权限不必增加到视频的 9 个勾选框。
SEC-02 [CODE] 新建文件夹只检查 list；需新建/管理能力与服务端拒绝用例。
SEC-03 [CODE] 保存 handler 只检查 modify；service 必须校验编辑锁，
  当前用户/令牌、基础版本与审批状态，拒绝绕过界面的提交。
SEC-04 [S] versions 增加 UNIQUE(file_id,seq)，同文件版本变更、回滚和
  审批写入需要事务行锁；并发提交不得重复版本号或出现 lost update。
SEC-05 [S] 同一文件有效 pending 要有数据库约束；审批结果只能从
  pending 原子跃迁一次；重复审批、文件已删、权限已撤、基础版本过期
  需要确定错误/冲突状态，不得无检查直接覆盖。
SEC-06 [S] blob 落盘和 DB 提交须有可恢复的临时写入、校验、原子发布、
  异常清理/垃圾回收策略。成功响应必须能读出对应内容。
SEC-07 [S] 回滚会删除目标版本后的所有历史，属于破坏性动作；
  是否保持此规则必须业务确认，并补二次确认、操作审计及灾难恢复。
SEC-08 [S] 认证会话加有效期、吊销、生产 HTTPS/Secure cookie、
  CSRF/Origin 检查；生产禁止默认/演示密码。
SEC-09 [S] 无权文件的名称、检索命中数量、授权主体、blob 地址不得泄露；
  浏览器直访、搜索和目录树都要授权测试。
SEC-10 [S] 文件/目录名、DOCX 转 HTML、搜索高亮、SVG/HTML 上传均要 XSS 测试。

四、PostgreSQL、前后端构建与远程部署补充
--------------------------------------------
DB-01 [S] v2 DDL 沿袭 SQLite 表模式；需要 FK/删除策略、CHECK、
  唯一性、必要索引、目录防环、合适的 BOOLEAN/JSON 约束。
DB-02 [S] CREATE TABLE IF NOT EXISTS 不是增量 schema migration；
  采用版本化迁移记录、失败中止和事前备份。
DB-03 [S] 中文逐字插空格 + phraseto_tsquery(simple) 要用真实中文、
  ASCII 混排、标点、百分号/下划线等样本测；LIKE fallback 的通配符需转义。
ENG-01 [S] Go embed 资源必须位于声明它的 Go 包下；
  明确 web/dist 复制到可 embed 目录的构建步骤。
ENG-02 [S][CODE] Node 用 mammoth，v2 DOCX 改为自研最小渲染器；
  明确表格/图片/列表/格式等不支持边界，复杂文档不能宣称完全对等。
ENG-03 [S] MP4 播放器 seeking 需要 Range/206 验收；仅检查 raw=200 不够。
ENG-04 [S] 远程切 8091 前使用隔离 DB/端口验证，备份 pg_dump+blobs，
  不硬编码 PostgreSQL 演示账号密码，有可操作的 rollback 步骤。
ENG-05 [N][S] 保留原 49 项检查作为历史基线，新增安全与文本用例；
