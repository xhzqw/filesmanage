二、截图/视频已实证与尚未实证范围
-----------------------------------------
视频强证据：
 - 组织树、组和成员卡片；
 - 工作组/用户的文件夹动作授权，权限继承、叠加；
 - 授权截止时间和“仅本目录”；
 - 目录文件表、文件上传、多媒体/文档预览；
 - 在线富文本式编辑界面、编辑锁、旧版本预览；
 - 版本表、回滚警告；
 - 检索入口与检索结果，预算类审批和决定弹窗。
中等证据：
 - 跨部门共享的实际视图；
 - 审批通过后具体版本数和解锁条件；
 - 具体文件类型与在线编辑格式的对应关系。
没有由所见帧直接证明的完整能力：
 - 回收站恢复/永久删除，关注增删，统计指标的计算，导出 CSV 格式，
   共享权限所有配置项及全部异常分支；
 - DOCX 二进制回写、并发同刻冲突的数据库保证、服务器 API、
   PostgreSQL 查询策略；
 - 视频网页的精确 CSS 像素尺寸与色值。
这些均不能虚称“视频已演示”，但用户已决定首期新增的五项必须完整交付，
故应作为“产品设计 + 测试契约”，不是“视频实证行为”。

三、与 SPEC.md v2 及 Node 行为的冲突
-----------------------------------------
DIFF-V01 [P0] 视频约 03:05 是富文本式编辑体验；SPEC v2 §0 明确
“真实 docx 二进制回写不做”“在线编辑仅文本类”；
Node public/js/pages/editor.js 用 contenteditable.innerText 保存 text/plain，
格式效果会丢失。必须决定富文本的受支持文件格式与存储语义，
并把视频原样保真/功能范围分开签收。
DIFF-V02 [P0] 视频回滚会删除目标后续历史；对新系统的版本可恢复性
产生强影响。SPEC 继承了该行为，但是数据库事务、审计、二次确认不够。
DIFF-V03 [P0] 视频在编辑和审批间保留锁；
旧 Node server/app.js 只验 modify 就能 save，缺乏强制锁主和基准版本校验。
DIFF-V04 [P0] 视频工作组/授权是核心；
旧 Node 对 POST ACL/DELETE ACL 只要求已登录，存在越权风险，
不能将错误的安全行为迁移为功能。
DIFF-V05 [P1] 视频使用 /organization?op=group；
SPEC 用 /org。推荐兼容，避免演示导航失效。
DIFF-V06 [P1] 视频文档预览包含多页阅读器 UI；
v2 自研最小 DOCX 解包只能处理部分段落/标题，不支持复杂排版保真。
需定义容许降级和参考样本，不可说完全对等。
DIFF-V07 [P1] 视频含真实媒体播放器；应测 206 Range、
Content-Type 和 seek，而非 200 即完成。
DIFF-V08 [P1] 视频展示共享文档入口；
共享授权应与目录 ACL 明确区分，验证同一资源在不同视图下的生效权限。

四、Plain Text-A 视频规格书写法
-----------------------------------------
每个页面应按以下字段写完整可复制文本描述：
  VIEW_ID / URL / 触发入口 / 前置账号角色 / 页面区块 / 可见文案 /
  工具栏操作及其 enable 条件 / 选中/空/加载/错误/成功状态 /
  点击动作 / 请求契约 / 持久化数据 / 权限 / 审计 / 视频时间戳 /
  图像参考 / 自动验收 ID / 异常与边界用例。
每项标注 [VIDEO] 或 [DESIGN]；不允许把推测性产品设计写成演示实证。
视觉基线要排除浏览器 chrome、字幕、视频播放器外围、指针。
中文文本精确转录若仅靠低分辨率截图无法确认，标记 VERIFY_TEXT；
不擅自写成必须逐字一致。
注：以上时间为近似场景范围，不是逐条动作精确到秒的音视频转录。

五、Plain Text-B 文件保真范围
-----------------------------------------
视频的内容展示不等于证明文件原始字节没有改变。
测试以 UTF-8、BOM、LF/CRLF、Tab、前后空格、超长行、尾部换行、
HTML 特殊字面量、无效 UTF-8、混合换行、并发版本冲突为固定夹具。
打开/预览不改字节；支持的文本编辑保存后要保持未改动的结构和原编码；
不可编辑格式只读，给出提示；XSS 字面内容不能执行。
富文本另立持久化载体和格式；不能把 WPS Ribbon 当作 Plain Text 的形式要求。
视频没有直接展示以上字节级测试，属用户要求的新增工程验收契约。
