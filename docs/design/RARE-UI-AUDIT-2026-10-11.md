# Rare UI 实施审计 — 2026-10-11

## 范围与证据

基于远端主线 085cae6 的 React 前端做静态检查。当前项目并非“没有 Rare”：有 46 个 TSX 文件引用共享 Rare 适配层；现有 `RareButton`、`RareSelect`、`RareTabs`、`Dialog` 已投入使用，原生按钮/输入元素主要由共享适配组件封装。但存在 36 个 CSS 文件，组件复用并不等于页面结构统一。

## 根因

1. **缺少通用数据工作台模板**：应用有共享控制组件，却没有统一约束“顶栏 + 筛选 + 结果表 + 按需详情”的布局结构。部分功能仍采用独立页面表格及每行完整编辑表单，窗口窄时横向溢出。
2. **布局策略碎片化**：全局 `theme.css`/`visualSystem.css` 与特性 CSS 并存，跨视口的列优先级、滚动所有权、详情区收纳缺少统一契约。
3. **业务状态复用不足**：审批、回收站、权限、协作等存在各自的状态徽章和行操作容器；需要提炼共享 StatusBadge 和表格行动区，但不能统一业务状态含义。
4. **验证缺口**：已有浏览器工作流覆盖审批意见，但旧用例依赖“意见输入框出现在表格行内”的 DOM 结构，而非完整的用户决策流程。

## 第一批落地：审批工作台

- 将页内 tab 改用 `RareTabs` 的键盘契约并赋予 ARIA 关联。
- 增加搜索、发起记录状态筛选、主动刷新；保留通知、未读、历史时间线、多级审批、深链定位。
- 通过、拒绝、撤回经确认对话框；评论只在决策时提交，409 触发刷新，非最终通过不得报告新版本已生成。
- 解除输入框撑大操作列的问题；独立滚动的紧凑数据表格，窄面板保留文件、状态/操作和关键摘要，通知/时间线改为按需侧滑而非堆在列表下方。
- WF-31 浏览器工作流更新为“打开对话框、填写意见、提交、切换我发起的、核对意见”的真实使用路径。

## 跨页实施顺序

| 优先级 | 范围 | 治理目标 |
|---|---|---|
| P0 | 审批工作台 | 窄屏可操作、状态直观、决策弹窗；本批已修改，待远端验收 |
| P1 | 共享数据列表与状态 | 沉淀 `DataTableSurface`、`StatusBadge`、`TableActionGroup`；统一行高、列优先级、滚动与标签语义 |
| P1 | 文档 / 搜索 / 关注 / 分享 | 统一文件名、时间、操作区、空态和筛选，不隐藏必要操作 |
| P2 | 组织 / 权限 / 管理角色 | 工作区分栏与快捷配置，减少重复边框和冗余说明 |
| P2 | 回收站 / 版本与预览 | 操作密度、状态语义、弹窗/抽屉；保留恢复目标和冲突处理 |
| P3 | CAD / Office / 登录 | 校准外层控件、响应式和样式 Token，不侵入第三方渲染内容 |

## 不可回退的设计约束

- 桌面默认紧凑行约 32–38px，必要时配第二行辅助信息，禁止空内容单行撑到 80px 以上。
- 不采用整个页面纵向大卡片串联；按工作流优先使用分栏、单结果面板、按需打开的侧栏/对话框。
- 窄屏首屏至少看见“文件主体 + 状态（有状态时）+ 主操作”；低优先级字段移动到可访问详情，禁止整页水平溢出。
- 所有新增表单控件优先经共享 Rare 适配层，保持原生语义、键盘焦点与真正模态；状态色必须来自语义 token。
- 不通过增加全局样式覆盖数目来冒充设计统一，先复用业务控件，再删除重复 CSS。
- 任何审批操作保留既有 API/权限/版本语义，不能为视觉效果删除通知、历史、多级节点或审核意见。

## 验收

仅远端运行构建、TypeScript、自动化和浏览器检查。至少复核 390px、768px、1366px 和 1440px，检查审批表头/行、窄屏文件名/状态/操作、侧面板可达性、键盘 tab、评论决策、通知与历史。复核结果不得将未运行项目记为通过。
