# Visual System V3 — 统一几何与视觉层级

状态：IMPLEMENTED（开发环境）。批准依据：2026-10-09 用户明确指出现有 UI 不统一、纯直角不符合预期。

## 1. 对 V2 的覆盖范围

本设计契约仅在**形态 / 圆角 / 视觉容器组合**方面优先于
`PRECISION-WORKBENCH-V2-SPEC.md` 中的「0-gap 方角嵌合」和
`--radius-xs/sm/md = 2/4/6px`。保留已验证的色彩对比、操作语义、
高密度表格（32/26px）、40px 顶栏、28px 目录行、24px 状态栏、
焦点轮廓、业务逻辑和层级导轨。

## 2. Geometry tokens

| Token | Value | Use |
|---|---:|---|
| `--radius-xs` | 4px | 小标签、键位提示、微型控件 |
| `--radius-sm` | 7px | 按钮、输入框、导航项目、树行 |
| `--radius-md` | 11px | 表格面板、媒体舞台、菜单 |
| `--radius-lg` | 15px | 主工作区、侧边栏、业务卡片 |
| `--radius-xl` | 20px | 对话框、登录卡片 |
| `--radius-pill` | 999px | 版本徽章及明确的胶囊标签 |

全站几何令牌统一在 `web/src/theme.css` 定义，
`web/src/visualSystem.css` 只保留布局与响应式组合，
`web/src/main.tsx` 在 `theme.css` 后加载该样式。组件不得引入任意
3/5/9/13 等独立半径，不得在独立表面使用 `border-radius:0`。
只有完全贴边的内部构造、输入内嵌区域、浏览器原生视频内容可不额外设角，
但其**可见外层必须裁切到所属表面半径**。

## 3. Surface hierarchy

1. 顶栏、侧边栏、主工作区采用 15px 圆角 + 1px 中性边框 + 极轻阴影；
   shell / panels gap = 8px，防止相邻区域形成大面积方直角硬接缝。
2. 内容工具栏、面包屑、表格采用 7/11px 圆角，小间距内嵌；不增加数据行高。
3. 卡片、权限工作台、浮层统一 token 及轻量投影；菜单内部项目采用 7px。
4. 视频、图片、CAD、在线编辑舞台使用 11px 裁切，消除预览独立样式割裂。
5. 小屏把 frame 间距压缩到 5px；禁止以额外边距造成横向溢出。

## 4. 不可回退约束

- 必须保留带键盘焦点的明显 focus 状态，不得用无对比度阴影替代焦点轮廓。
- 新样式不得用全局 `*` 或 `!important` 覆盖业务状态；只在明确定义的
  shell / surface / control 上治理，避免穿透 CAD Canvas 或 Office iframe。
- `Preview` 页面独立滚动，表格和目录树的滚动宿主不得因圆角裁切而变化。
- 视觉验收需要覆盖登录、文档、预览、组织与权限、回收站、弹窗、响应式；
  关注几何 computed styles、选中态、键盘焦点及是否发生横向溢出。

## 5. 响应式布局与文件数据表

- 桌面保留可拖拽目录侧栏。宽度 701–960px 时，将持久化的侧栏宽度
  **上限限定为 200px**，保证右侧文档工作区可用。
- 不大于 700px：目录树和主工作区上下排列，目录树高度 128–180px；
  收起无意义的横向拖拽手柄。顶栏保留导航入口、全局搜索、账户和退出入口。
- 目录工具栏和文件批量操作在窄屏 **换行而不是压扁或遮住控件**；
  弹窗限制在 viewport 以内，并保持最小操作触达区。
- 文件表格仍保留六列和高密度布局，不在手机上隐式丢弃操作列。
  `.work-body > .table` 是独立可横向滚动的容器；
  必须通过 `contain:paint` 阻断 732px 表格影响移动设备的 CSS
  layout viewport。仅设置 `overflow:auto` 不够：真实 Chrome 曾将
  390px 页面自动扩大到 725px。
- 组织工作台在不大于 1024px 时单列布局；标签栏如超过视口，则
  在标签栏内部横向滚动，不能扩大页面。

## 6. 验收与复测

目标机执行 `node scripts/ui_geometry_check.mjs`。
已通过 **81/81** 圆角、真实 DOM 尺寸、窄屏、弹窗和导航测试。
宽度覆盖 1440、820、600、390、320px，并进一步使用 Chromium
移动设备仿真，逐一确认 `innerWidth` 等于实际设备宽度、
`visualViewport.scale=1`。不得仅检查 `documentElement.scrollWidth`
来判断是否溢出，必须同时验证页面是否可横向滚动以及表格容器内部
是否独立滚动。

本套门禁只验证确定性几何约束，不能代替所有页面的视觉人工审查。
业务门禁还须继续执行 `scripts/build.sh --with-tests` 和
`scripts/browser_journey_check.mjs`，且只能在目标机运行。

## 7. 组件 CSS 所有权与静态门禁

- **形态的最终事实来源是组件自身**：文件表格行菜单、上传队列、
  图片 / 视频预览、命令面板、右键菜单、组织导航、权限工作台、
  协作卡片均直接声明 V3 `--radius-*` / `--shadow-*` 变量。
- `visualSystem.css` 专注全站令牌、应用壳层、独立页面及响应式组合，
  不再为已迁移组件复制相同的圆角与阴影定义；避免单纯靠加载顺序
  隐藏旧角度。
- 新增 `scripts/ui_style_governance_check.mjs`，由远端
  `scripts/build.sh` **每次构建自动运行**。对 feature / shared 组件
  禁止写死直角、随机像素半径和额外的全局组件几何覆盖；真实圆形和
  子元素继承半径例外。
- 旧 `theme.css` 中的 V2 方角定义已迁入 V3 令牌，不再通过
  `visualSystem.css` 重定义变量。门禁还会检查核心主题的半径
  必须全部来自令牌，禁止新旧几何共存。

## 8. V4 操作效率与权限工作台可达性

- 文件名仍是可选中的文本，不能改为隐式打开链接。窄屏（≤700px）
  和触屏设备在文件名同列显式提供「更多操作」，打开与桌面右键同一
  `Menu`（可键盘访问，包含打开、编辑、重命名、移动、下载、删除）。
  禁止仅依赖 hover 才显示操作。
- 权限页在 ≤850px 时采用「紧凑资源树 + 独立滚动详情」两段式：
  目录树占可用高度约 28%，剩余空间交给授权记录和授权表单，
  避免长表单把整页推走。记录表和组织成员表允许在自身面板内横向
  滚动，不允许撑大外层页面。
- 权限页子导航使用带选中背景及高对比下划线的统一状态；搜索目录时
  选中项与资源树一致，支持 `aria-current`。授权记录展示服务端返回的
  直接授权条数，明确其不是最终有效权限。
- 浏览器几何门禁包含权限页 820、600、390、320px 目录和详情的
  有效显示高度、独立滚动宿主，以及手机文件名快捷菜单真实可用性。

## 9. V5 一致的菜单、敏感授权与大列表

- 文件操作入口（桌面悬停栏、窄屏文件名操作、键盘 Shift+F10
  和右键）只使用共享的固定定位 `Menu` 浮层，不能在表格内部放置
  会被 `contain:paint` 裁切的另一份内嵌菜单。
- 直接授权始终两阶段确认；涉及下载、修改、删除或移动等高影响
  动作时，摘要必须显示目标目录、主体、范围、期限和具体动作，并且
  由操作者显式勾选确认后才能提交。修改任何表单字段会使旧摘要及
  风险确认失效。前端门禁只保障交互，服务端 ACL 校验不受替代。
- 成员表和工作组列表首次分别渲染最多 100、60 项，用户点击
  「显示更多」逐步增加可见项；切换筛选条件重置显示上限。
  原始数据及筛选匹配数不能被截断；服务端单次上限仍需提示。
- UI 自动检查桌面操作列菜单可在横向滚动后显示在视口内、
  其阴影与圆角采用统一设计令牌；权限专项浏览器测试绝不提交
  真实授权，仅验证高风险操作需要勾选和修改范围使确认失效。

## 10. V6 大列表验收与只读 QA 会话

- 成员表、工作组目录、组内成员卡片各自采用分批显示（初始分别为
  100、60、100），不会一次构造上千个 DOM 节点。筛选应对全集
  生效、保留真实总数，不能把只渲染的首批误当作所有数据。
- 远端执行 `node scripts/org_large_data_browser_check.mjs`，以真实
  Chrome 页面 + **仅在当前标签页拦截的模拟读取响应** 验证 1000
  名成员、400 个工作组和一个 420 人工作组；数据从不写入数据库。
  检查首屏上限、逐步显示、筛选准确性及基本响应时限。
- 权限 API 与权限浏览器测试共享 `scripts/qa_session.mjs` 验证过的
  admin 会话：本机仅支持远端目标上的回环 HTTP，缓存仅写入
  `.secrets/qa-admin-session.json`（0600、git 忽略、最多 2 小时），
  每次复用前向 `/api/me` 验证。若过期/失效才向正式登录 API
  请求新会话；遇 429 直接报告并尊重 `Retry-After`，严禁通过
  清空限流、换 IP 或重启服务绕过。登录表单和登出行为仍由独立的
  文件业务旅程回归验证。

## 11. V7 组织列表游标分页和 CAD 按需加载

- `GET /api/users` 与 `GET /api/groups` **不带**分页参数保持兼容的
  数组响应和现有 1000 项上限；**携带** `limit`（1–200）或非空
  `cursor` 时使用主键游标分页，返回
  `{items:[],nextCursor:""}`，末页用空游标表示完成。无效参数
  必须 400，未授权必须 401/403。所有请求始终由服务端检查管理员身份。
- 管理页面逐页读取直到空游标，不再把 1000 项旧上限当作真实全集；
  工作组界面合并后按名称重新排序，保留原有视觉顺序。遇到网络错误
  或不前进游标直接失败，不显示看似完整的截断数据。分页在列表
  变化期间保证同一主键不重复；不承诺跨多个请求的事务快照。
- 三维 CAD 路由通过 React `lazy`/`Suspense` 延迟加载整页
  ModelViewer 模块；模型解析器和 Three.js 本身继续按格式动态导入。
  文件首页无需下载 CAD 预览代码。通过远端 Vite 构建产物的
  拆包检查和原有真实 CAD 业务回归验收。

## 12. V8 CAD 场景资源与按需渲染

- 静态模型不能常驻 GPU 60 FPS：OrbitControls 实际变化、图层、
  装配零件可见性、选择、投影与画布尺寸变化时才调度渲染；
  阻止后台标签页提交帧，并在页面恢复时刷新。
- Viewer 卸载或切换模型 ID 时必须清理 scene 中去重后的 BufferGeometry、
  Material 和 Texture、网格坐标辅助资源、OrbitControls、ResizeObserver、
  事件监听器、未完成下载和 WebGL 上下文。不得改写模型的源材质或
  平白为每个 mesh 再分配材质； glTF/OBJ 的源贴图应保留。
- 模型字节同时检查声明长度和实际分片累计长度，无长度头和分块
  传输也不能绕过 256 MiB 的浏览器内联预览保护。
- 远端 `mc02_assembly_check.mjs` 使用真实 WebGL draw 调用计数验证
  静态模型 750ms 后不持续绘制，以及零件隐藏操作能触发绘制；
  同时维持两实体装配、显示/隐藏、恢复视图和高亮的视觉回归。
