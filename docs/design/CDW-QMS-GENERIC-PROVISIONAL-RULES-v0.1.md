# CDW 缺失质量制度通用工作合同 v0.1（非受控草案）

> **DRAFT / NOT CONTROLLED / NOT EFFECTIVE。** 本文件供 filesmanage 工作台方案 A 进行业务建模、草案评审和模拟验收，不是企业已批准制度、真实授权证明或合规报告。创建日期 2026-10-16。禁止凭本文件生成真实签名、法规报告成功凭证、产品放行许可或受控文件生效标记。

## 0. 来源、边界与解释规则

参考仓库 `docs/流程参考文档/` 内 ZS-QP-01、02、09、10、17、19、20、23、24、25、26 原文和 G1–G6 CDW 合同，承接已明确的 1–76 项决策。77–83 项在本文按建议 A **暂时建模而非替用户正式拍板**。

未见正式原文或有效授权：①《产品设计历史文档管理规定》；②《产品器械主文档管理规定》；③ WI-ZL-09《医疗器械召回管理制度》；④ WI-ZL-20《医疗器械不良事件监测制度》；⑤现行重要供方质量协议；⑥已正式生效的签批授权矩阵；⑦独立《工程变更控制程序》（若企业已制定）。已有 ECR、ECN、设计变更单表单，但不能只凭文件名断定现行有效版。

**约束优先级**：适用且有效的法律法规和监管要求、正式生效受控文件及授权、高位审批程序、已批准工作流模板，最后才是本草案。来源冲突进入 `policy_authority_pending`，不得自动“按通用规则”盖章通过。

**通用系统行为**：
1. 任务派发/逐级验收、正式文件批准、受控发行、部门签收、个人阅读、培训考核、岗位资格、实物处置、法规报送必须为独立责任和证据，关联而不互相自动代替。
2. 正式候选稿、每次转换和签章、最终发行物分别保存稳定 ID/内容 SHA256；审批只能针对固定版本，部门签收只能针对冻结的发行物和清单。
3. 真正审批须验证当时有效的业务职务、任命、权限范围及真实操作人。IT 管理员无当然审批权；未知授权允许起草、派工、准备评审，不允许正式批准、生效、代签。
4. 不得覆盖历史交付、签名、文件版次、收件确认、失败检查和撤回事件；更正记录采用原值/新值/理由/操作人/日期的追加事件。
5. 正式发行采用“已批准候选稿→冻结发行产物→批准分发范围→发行→部门接收→适用阅读/培训→生效→旧版回收”；紧急撤回后没有合法版本必须显式标识。
6. 平台无经单独批准的集成时只管理任务与凭证，不直接修改 ERP/WMS、设备状态或监管系统。内部“已提交待办”不等于实体或法定履行完毕。
7. 法规报告分类、适用范围、接收单位、时限、方式只能经质量/注册授权人员核实**当时有效法规**后配置；不编造统一法定天数。

## 1. 草案 SOP-A：DHF 设计历史文档

**范围**：ZS-QP-09 规定的设计开发项目、设计输出与生命周期证据。**主办**：项目负责人统筹；专业职能提交；独立人员参加需独立评审的阶段。

- 建立完整交付清单：立项/项目计划、DID、输入/输出 DTM、风险、设计输出、设计与技术评审、验证、确认、临床/法规适用资料、设计转移及变更记录。
- 每条需求单独编号并关联产品规范、输出、验证和确认；后续变更需有真实批准的设计变更表及 DID、DTM、风险与试验影响清单。风险未核验时不得以“技术评审已完成”替代。
- 各阶段所需交付首先完成编制、审核及适用批准，然后才能进行相关技术评审；独立评审人员参与真实签署。关键问题未解决时阻断门禁；非关键有条件通过保留责任与日期。
- 研发样机探索与正式交付文件分区；X 类试验数据不能自动成为正式生产指令。D8 项目结题独立于 D9 上市后监管/退市任务。
- ZS-QP-09 把 DHF 具体审批资格进一步交给《产品设计历史文档管理规定》；**在确认其受控依据或公司正式核定规则之前，不启用 DHF 正式批准**。

**草案模板** `cdw.qms.dhf.v0-draft`；必要证据：阶段、角色、交付 SHA、DID/DTM 关系、风险/验证、异议、签名及批准依据。

## 2. 草案 SOP-B：DMR 器械主文档

**目的**：确定某产品/型号适用的制造、检验、包装和标识要求，不能与记录实际作业的批记录混为一谈。

- 受控清单包含产品型号/配置、BOM、技术图纸、作业指导、工艺及软件烧录版本、设备工装、特殊过程确认、检验与验收方法、包装标签/说明书等；不适用项留获批依据。
- 按 ZS-QP-09 允许从设计阶段 X 版转正式版，但 X→A/0 是需审批与受控发行的转换，不得仅改文件名。DMR 专有版次规则及审批角色待专门规定核验。
- 生产指令冻结批准时适用的 DMR/每个文件版本 ID、哈希与实施时点。已开始的批次遇正式文件换版，生成生产、质量、研发影响评估；既有批记录不重写。
- 必要的验证、确认、培训、生效条件缺失时禁止把 DMR 标记“有效”。旧电子版退出普通执行入口，纸质副本逐份回收并保留异常。

**草案模板** `cdw.qms.dmr.v0-draft`；缺授权进入 `requires_dmr_authority_basis`。

## 3. 草案 SOP-C：召回与忠告性通知

**说明**：ZS-QP-25 忠告性通知可以建任务，**不等于 WI-ZL-09 的法定召回义务已完成**。

1. 发现：质量投诉、不良事件、检测偏差、监管沟通等登记稳定案件 ID、首次知悉时间、来源及证据。
2. 研判：质量/法规牵头调查型号、批次/序列号、在库、在途、已售、客户清单、伤害风险和可能受影响范围。紧急实物隔离由有权实体部门完成。
3. 批准：是否召回、等级、范围、时限、告知对象、监管报告及对外批准角色必须根据有效规定核验，保存权威依据。**不得自动声明正式召回或虚构报送回执。**
4. 执行：批准通知版本、分发客户清单、发送时间/渠道、交付与确认、跟催、各批次回收数量、无法回收原因、隔离/销毁记录分别留证。
5. 验收：收件人确认不等于实物已回收；须进行数量调和、效果评估、风险管理与 CAPA 关联，由授权人员决定关闭并保留真实监管回执。

**草案模板** `cdw.qms.recall.v0-draft`；法规规则未核定进入 `regulatory_basis_pending`。

## 4. 草案 SOP-D：医疗器械不良事件

- 受理设备相关投诉或潜在伤害信号时，创建独立案件：首次知悉时间、产品型号与批次、事实经过、严重性初判、资料与责任岗位。
- 患者姓名、诊断、病案号等仅能在受限信息域访问；普通工作列表显示去标识化摘要，对外导出/提供副本应独立授权留痕。
- 法规/质量专岗对“是否可报告、按什么地区和制度、何时、向谁、需哪些材料”作出有源依据的决定。不配置猜测法定时限，禁止用旧样式表单冒充成功提交。
- 不良事件、投诉、CAPA、召回与风险复评互相关联但不能合并完成；即使不立 CAPA，涉及新危害仍须独立判断风险复评。
- 正式报告、实际提交、监管回执、补充报告及调查结案分别登记真实时间、证据与操作者。

**草案模板** `cdw.qms.adverse-event.v0-draft`；缺 WI-ZL-20 时正式法规节点须阻断并转授权人员核验。

## 5. 草案 SOP-E：首次重要供应商质量协议

**依据**：ZS-QP-10 §4.2.11。仓库中仅找到“作废”目录的质量保证协议范本，不能作为正式新签模板。

**合同字段**：双方主体、授权签名、所涉物料与技术标准版次、质量与检验责任、变更通知和预批准、追溯和记录保留、偏差/CAPA、审核与供应商协作、分包、保密与知识产权、召回配合、有效期和解除、争议解决。合同期限、赔偿和通知天数由有权商务/法务审核，不自动猜测。

**流程**：供方评价合格 → 识别重要物资适用性 → 编制协议 → 审查签字资格与条款 → 双方真实签署 → 对对应物资打开首采资格。合格供应商状态与协议生效状态独立；缺协议不允许系统自动宣称重要物资首采已通过。

**草案模板** `cdw.qms.supplier-quality-agreement.v0-draft`。

## 7. 草案 SOP-G：ECR/ECN 工程变更

**现有表单**：QP-09-JL12 A/1 ECR、QP-09-JL14 A/1 ECN、QP-09-JL20 A/0 设计变更单。使用前必须与文控核验现行版本；若已有独立《工程变更控制程序》，以有效原件为准。

- ECR 申请记录申请原因、变更前后、设计输入/输出、BOM/图纸/工艺/软件、产品/批次、库存与在制及市场在用产品影响。
- 研发、质量、生产、采购，以及适用的销售/法规等作出各自风险、验证/确认、临床/注册、再确认、培训、库存与采购影响评估；关键缺失项阻断。
- 正式授权审批冻结具体变更范围，不能以工作任务验收代替批准；批准前不得直接替换有效生产指令。
- ECN 按批准范围生成通知并关联 DMR、DHF/DTM、风险文件、供应商、培训、文件发行、部门签收、旧版回收和适用实物处置的独立义务。
- 结案须核对每一项验证和受影响范围，不得把“文件已更改”当作 WMS/ERP 实物状态已改变。

**草案模板** `cdw.qms.engineering-change.v0-draft`。

## 9. 首例流程实践：49A 的真实勘误题

**问题核验**：ZS-QP-23 A/0 §5.1 《内部审核控制程序》引用错误编号 `ZS-QP-10`，正确应为 `ZS-QP-18`；§5.3 《采购控制程序》对应 `ZS-QP-10` 保持不变。该文件还有若干错误页眉/程序名，需逐页复核。

**模拟路径**：登记缺陷→原件和错误定位→QP-01-JL03 编制变更申请→管理者代表审核→总经理正式批准（用户决定 56A，对应 ZS-QP-01 §4.2.3）→文控复核版本及页眉→固定批准稿和发行物 SHA→发行→部门签收/必要阅读→受控生效→按份号回收旧纸质副本。QP-01-JL03 中与此程序不一致的审批栏单列勘误，不让旧表单减少程序必须审批人。

**版本与真实性**：ZS-QP-01 §4.3.4 规定小改版次调整、页数变化等情形可能升版；在版面核验前不得假定新版本一定是 A/1。本草案不代表已建立真实业务审批、不代表有人签署、不代表监管或用户已签收。

## 10. 最小工程验收与待解锁项

1. 正式授权缺失：可完成草稿与任务验收；调用正式批准须阻断并报告 `policy_authority_pending`。
2. 最终发行文件有独立 SHA；分发签收只能基于冻结 manifest；普通预览不泄露已批准但未生效稿。
3. 不良事件/召回若无真实法规依据及报告回执，不能显示“法定报送已完成”。
4. 供应商合格但质量协议缺失，重要物资首采仍为 `agreement_required`。
5. 日期批号相同的两次收货须能按不同内部收货 ID 追溯。
6. ECR/ECN、投诉、CAPA、风险复评、培训和文件发行彼此关联但不互相冒充完成。
7. 测试 49A 必须使用隔离样例、真实来源哈希和模拟权限；不生成假真实签名或假签收。
8. 待正式原件和授权补齐，进行差异审查与模板升版，不原地改写任何已批准历史实例。

**解锁前置**：DHF/DMR 签批规定、召回/不良事件法规适用性核定、有效质量协议模板、正式签批人任命、工程变更专用程序（如存在），均需由公司依法依制度真实审批。
