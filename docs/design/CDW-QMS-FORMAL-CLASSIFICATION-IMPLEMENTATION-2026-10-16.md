# CDW 正式审批文件分类门禁工程记录（2026-10-16）

**仅为工程设计和验收记录，不是已正式发行的企业制度。**

## 本轮实施

现有 `cdw_document_profiles` 增加 `approval_class`（`pending/general/qms`）、核定说明、实际核定人、文控角色绑定、核定时间及对应数据库不变量。此前未分类的文件默认 `pending`，绝不默认当作普通文件。

1. 文控对真实文件完成一次性分类；分类人必须有**当前有效且覆盖该文件**的 `document_control` 业务角色，管理员身份不能替代文控角色，分类操作由既有审计、幂等和事件机制记录。
2. 文件名包含质量受控文号或显著质量制度特征，以及已有受控文件资料的，不能归为 `general`。这是**保守的负面规则**，不是“所有 QMS 文档均可从文件名识别”的保证；可疑及未识别文件仍须人工核定。
3. `pending` 文件不得发起正式审批。已明确 `qms` 的文件必须走 QMS 模板并核验其当前有效受控制度发行 ID、与该依据匹配的审批人角色；`general` 不得套用 QMS 发行依据。发起、签署、已批准稿的发行准备、签发及生效持续核验。
4. PostgreSQL 另有提交实例前置触发器，禁止通过直接数据库 INSERT 使用普通模板审批 QMS 文件；已登记的 `qms` 文件不能直接 UPDATE 降级为 `general`。
5. 前端 `CDWFormalInitiate` 不再由发起者自行选择审批用途。文件选定后加载服务器分类，未确认前显示可留痕的文控分类入口，错误归类将被后端拒绝。

## 已知边界

- 分类时的 `document_control` 角色技术有效性已校验，但**真实授权书和岗位任命在文本内容层面的有效性、授权链独立审核、法规资格**尚需单独建立任命依据证据与实质复核机制。
- 文件名与当前文控资料无法构成100%质量分类识别能力，故要求**先分类再正式审批**；管理员不能靠选择普通流程跳过已登记的 QMS 类别，但拥有合法文控角色的人员仍须遵守公司实体制度和真实职责。
- 已有业务文件若尚未核定 `approval_class`，后续新审批会被安全阻断，需要经过真实文控归类。这是一项明确的不兼容安全门禁；先做数据核对，不能批量将原有文件自动标记为普通文档。
- `DHF/DMR` 的专属审批授权、召回与不良事件法规程序及 49A 原始文件勘误**未因本次代码变化而自动得到真实企业批准**。
- 实施只在开发环境和专用隔离 PostgreSQL 数据库执行测试，不创建真实公司批准或发行事实。

## 验收目标

`0059_cdw_formal_document_classification.sql` 需经过隔离 PG17 迁移；`TestCDWTaskPostgresTransactions` 验证未知类别阻断、普通文件文控归类、无权分类拒绝、QMS 文号不能普通归类、QMS 非法模板拒绝、数据库反绕过、制度依据失效阻断及 G2–G9 主线无回退。浏览器脚本验证无需用户手动切换审批类型及不同工作区宽度。
