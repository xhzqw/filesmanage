# CDW QMS 签批岗位任命证据门禁

状态：工程增量与验收记录，**不属于正式生效企业制度**。

## 权限边界

QMS 受控文件的审批人必须同时具备文件级技术审批角色、当前生效的审批程序依据及**针对本文件与确切审批节点的独立核验任命**，缺一则返回 `E_CD_QMS_APPOINTMENT_PENDING`，不可签署。普通非 QMS 流程保持现有兼容。

1. 管理员可将被任命人、签批节点角色、制度发行 ID、任命凭据发行 ID、有效期和任命条款说明登记为 `pending`。仅登记不能提供签批资格；提报人与被任命人必须不同。
2. **不是提报人、也不是被任命人的文控人员**，使用自己当前生效的 `document_control` 角色对凭据、岗位、适用范围、有效期进行独立复核，才可将任命转为 `verified`。文控核验及企业实体任命是两个不同事实；仅勾选“已核验”不能替代正式签署的任命原件。
3. 每次角色授予、审批启动、审批签署及收件箱授权均核验任命状态、受控依据、有效时间和匹配节点；签署审计快照写入岗位任命 ID。过期、被替代或撤回的受控凭据导致新签署被阻断，历史签署证据保留。
4. 数据库端按 `file_id+user_id+node_key+policy_release_id` 再次验证，阻断绕过 HTTP 直接写 QMS 审批结论；任命证据不可在审核通过后篡改，不能自行核验，变更须另起合法记录。
5. 新增待审核任命的登记/核验接口与现有工作台 UI，不新增第二套审批系统。HTTP GET 限文件可见的管理员或文控业务人员，避免其他一般阅读者查看人事任命材料。
6. 任务工作台新增独立「任命核验」视图，仅显示核验人有文控权限、文件可见且与本人无利益冲突的事项，支持非管理员文控人员直接核验。
7. 任命材料的政策来源与证据来源也走文件 ACL 交集；无权查看原件的人无法登记、查看待核验事项或完成核验。核验界面保留凭据的具体受控发行版本 ID、文件名和跳转入口，并提醒普通预览不能替代核验精确发行版本。

## 特别限制

- 技术层面能确认受控发行物“当前有效”、签批角色技术授权及独立复核事实，**不能自动理解任命书条款的实体合法性、签字真伪、医疗法规资格或者公司正式签批矩阵**；真实任命人及文控应核对原件内容。不得将任何“有效文件”任意声称为岗位任命书。
- `ZS-QP-09` 所委托的 DHF/DMR 专用签批原件，`WI-ZL-09` / `WI-ZL-20` 监管制度，以及 49A 案例的真实审批尚未因此形成法定合规结论。
- 通过对测试库的隔离 fixture 写入不能视为真实 QMS 人员任命；开发库不得生成伪造签名。

## 验收要点

隔离 PostgreSQL 上核对：未经核验禁止授予 QMS 技术签批角色；提报人和被任命人不能自审；由独立文控人员确认后仅对应节点有效；变更核验人、强制 SQL 签署、任命凭据失效必须阻断；同时原 G2–G9 审批/发行/签收主链须保持通过。Go/前端构建、接口契约及 18091 开发界面另行验证。
