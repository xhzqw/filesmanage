# Rare UI 组件接入与署名

本项目使用并改造了 [Rare UI](https://www.rareui.com/) 的动画 React 组件；其 [LICENSE](https://github.com/swamimalode07/rare-ui/blob/main/LICENSE) 包含 MIT、Commons Clause 及署名要求。Rare UI 是上游项目，不是本项目原创的组件库；衍生文件需保留来源说明和版权信息。

| 组件 | 来源与场景 | 改造说明 |
| --- | --- | --- |
| `GooeyNav` | 上游 [Gooey nav](https://www.rareui.com/components/gooeynav)；全局顶部八路由、权限视图、统计数量/容量切换 | React Router 替换 Next.js，CSS tokens 替换 Tailwind，蓝白品牌色、固定高度及 reduced-motion |
| `NotificationBell` | 参考上游 [Notification bell](https://www.rareui.com/components/notificationbell) 的交互规范；审批/生命周期通知 | 项目重写的轻量适配版，保留计数出现/消失、收到新消息摆动以及 reduced-motion，统一品牌色，不依赖 Radix |
| `RareButton`、`RareSelect`、`RareTabs`、`RareDataTable` | 本系统自建适配层，**不是上游组件** | 统一基础操作、输入、标签与数据表格；RareTabs 参考 Rare UI 的弹性指示方式增设不改变页面布局的 spring rail |
| `FolderResourceIcon`、`SpringActiveRail`、`FluidOrb`、`AnimatedCounter` | 自研的 Rare UI 风格实现；FolderResourceIcon 的开合微动效参考官方 [Folder component](https://www.rareui.com/components/foldercomponent) | 兼顾黄色文件夹识别、密集文件树、统计与低功耗；与官方放大式文件夹卡片不同 |

后续新组件必须区分“直接接入源码”“基于源码改造”和“参考风格自建”。高频表格/树行不得增加无意义动画；应保留键盘支持、焦点态、reduced-motion，颜色使用 `--brand-blue`、`--brand-cyan`、`--folder-fill` 与工程工作台 token。宽屏、笔记本、窄屏效果必须在远端验收。

## 第二批：公共交互控件（自建，非 Rare UI 官方源码）

- **Dialog**：新增统一紧凑标题栏及关闭图标，调用现有 `closeGuard` 防止提交中误关；首焦点仍进入表单字段，原有原生 `showModal()`、Escape、焦点恢复逻辑不变。
- **Menu**：使用 React Portal 避免受文件表格、目录树滚动容器裁切；保持键盘方向键/Home/End/Escape、光标定位、锚点焦点恢复及缩减动效。
- **RareSelect**：统一品牌样式并补齐 combobox ARIA、搜索高亮、跳过禁用项、活动选项自动滚动、禁止失效下拉继续打开；继续在原生 `select` 处理表单值。
- **Toast**：隐藏标签页期间暂停自动关闭计时，回到页面仍有反馈；保留模态框顶层提示与优先级/并发操作语义。

这些控件是按照 Rare UI 的交互理念和系统现有设计 token 自研实现，不宣称来自官方同名组件。

## 第三批：业务界面真实使用，而非只提供封装

- 组织权限的三个一级视图由普通文字按钮改为**实际渲染上游改造的 GooeyNav**。蓝色选中项从浅灰背景中分离并使用 spring 过渡；原有 URL 参数、未保存变更拦截和审计深链接保持不变。
- 权限详情的“授权列表 / 生效权限”改用 **RareTabs**，保持 WAI-ARIA 的选中和方向键行为；新建授权是单独操作按钮而非冒充 Tab。
- 组织管理的主要 Tab 采用蓝底白字的清晰选中态，保留弹性底部导轨、徽标计数和原始 tabpanel ID，不改变页面尺寸。
- 文件列表开始 **实际渲染 RareDataTable**，保留原生 `role=grid` 的多选/快捷键/拖动语义，选中行使用品牌蓝导轨。
- 文件工具栏移除常驻的四个禁用批量按钮，只在选中文件后显示带数量、操作和撤销选择的紧凑批量工具条；未选中时保留上传、建目录、排序、筛选和搜索的主要入口。

以上界面由品牌 token 控制，不引入官网示例配色；保持较低动画频次，兼容 `prefers-reduced-motion`。

## 第四批：全局顶部导航的真实 Gooey Nav

- `AppShell` 的单一顶部 `nav` **直接改为 Rare UI GooeyNav**；八条现有路由全部保留客户端跳转，选中状态由当前 URL 受控，不再复制 `NavLink` 冒充。源文件来自 Rare UI 上游源码的 React Router 适配（见首表）。
- 桌面导航在品牌蓝色胶囊之间呈现连续/分离的 Rare UI 弹性连接。公共 `GooeyNav` 的链接保留历史 `.active` 类，确保既有路由门禁和 `aria-current=page` 无需重写。
- 1210px 及以下使用**同一个 GooeyNav 实例**展开为紧凑纵向链接；隐藏动画连接、取消相互重叠并支持 Escape 返回菜单按钮焦点。方向键/Home/End 可移动链接焦点；Enter 仍由原生 React Router Link 处理。
- 新增 Chrome 验收必须断言：八个链接、品牌选中、桌面与窄屏 DOM 实际呈现、操作区域不遮挡、三档视口无溢出，以及已有 Dialog/Select/Menu 行为。

## 第五批：文件预览、审批与签章工作区

- **文件预览**：文件头从最多十项并排操作改为下载/签章/打印/文件格式专属入口 + `Menu`「更多操作」。移动、重命名、收藏、文本编辑、分享、删除保留权限控制及原业务对话框，其中删除显式危险色。二级动作默认收起，避免文件标题被挤压；使用已有 Menu 的 Portal 定位、方向键、Escape 和焦点恢复。
- **文件详情导航**：保留 WAI-ARIA `RareTabs`、六个原有 Tab id 及 `tabpanel` 对应关系，改成品牌蓝胶囊和 spring rail；减小页头空白，收紧操作密度。
- **审批/签章**：页面一级切换实际接入上游改造的 `GooeyNav`，`?tab=seals` 由路由状态驱动，浏览器前进后退、直接打开链接和页面刷新都会落在正确工作区；审批列表和签章库作为受限滚动工作台独立显示。
- **验收**：Chrome 检查至少 1440、900、390px 下审批视图深链接、切换和返回；已有文件时增加预览次级操作、键盘关闭、Tab/面板对应以及水平溢出检查，全部只读，不触碰数据。

## 第六批：文件资源树、工作组与委派权限、审批侧栏

- **文件资源树**：恢复此前隐藏的 `SpringActiveRail` 选中轨，选中目录只保留单层蓝色轮廓；搜索框引入统一内嵌图标、清空按钮与焦点样式，常驻冗长辅助说明改为无障碍描述。树的分层展开、Shift+F10 菜单、文件移动预检及 ARIA 树键盘路径保持原状。
- **工作组**：左侧主列表用单行图标、清晰的 cyan 选中轨和紧凑计数代替重复边框徽标；搜索可一键清空。详情仍保持右侧组员管理和添加流程，移除组员/删除组权限校验不变。
- **委派角色**：ACL 动作编辑增加实时已选数量和“全部选择 / 清空”两条局部状态操作；不执行权限变更，实际委派仍需原有预览确认及服务端权限检查。
- **审批侧栏**：侧栏原来的文字 Tab 改为真正的 Rare UI GooeyNav；点击整条审批记录可联动右侧详情，Enter/空格与现有“详情”按钮行为相同。筛选移除当前记录时选择第一条仍可见记录，并联动刷新流转历史，避免出现空白侧栏或过期信息。
- **回归**：远端 Chrome 覆盖桌面、普通笔记本、390px：目录搜索/选中轨、工作组主从一致性、审批侧栏选项和键盘入口；现有完整构建与权限行为门禁必须继续通过。

## 第七批：功能 UI 去重、权限工作台减噪

- 用户再次明确“功能 UI 重复是最不能接受的”。同一功能入口不重复，同一业务输入不再有不同的 UI 实现；形成明确的**共用功能层、业务流程层、布局层**。
- **单一 ACL 动作选择器** `PermissionActionPicker`：直接授权、快捷授权、角色委派共用全部状态/快捷选择/勾选/选中样式；仅根据调用场景传入允许的动作及预置模式。高风险授权审核仍由原流程控制。
- **单一授权基础字段组** `PermissionGrantSubjectFields` / `PermissionGrantScopeFields`：快捷授权和权限工作台保持同一主体类型、对象搜索、目录范围和有效期输入。不再复制前端实现或单独维护动作字典。
- **入口去重**：权限工作台只保留工具栏的“新增授权”；表格空状态不再重复按钮；进入创建态工具栏变为唯一“返回授权列表”，不在表单里再放一条“返回列表”。
- **去线条与布局**：资源/授权双栏只保留结构分隔、主行选中轨及危险确认；减少授权表的逐行线、快捷授权对话框的逐行线，以及目标文件夹选择器的内外双层框。排版、间距、前景层级是主分组手段。
- **门禁**：构建、组件治理、去重代码审计、只读 Chrome 页面验收；不得造成表单自动提交、授权变更、丢失键盘焦点或水平溢出。
- **横向去重**：快捷授权 Dialog 顶部关闭图标为唯一关闭入口，删去底部重复“关闭”；统计工作台将两组完全相同的数量/容量 GooeyNav 合并为筛选区唯一指标切换。两条用例均由组件治理脚本防止回归。
