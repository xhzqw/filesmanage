## 事实、技术决定和安全边界

1. V0.7.4 的只读环境公钥信任锚证明“某把密钥能验证签名”，**不能**证明“该密钥被授权代表这个 Gate 责任人”。V0.7.5 的登记凭证额外绑定唯一公钥指纹、用户身份、单一试点用途、有效起止时间和追加式状态事件。必须同时匹配 V0.7.4 的外部公钥信任锚，不能由客户端自行提交可信公钥或角色。
2. **签署载荷 V2** 使用 `DHF-PILOT-GATE-CANDIDATE-V2` 领域，并包含旧有冻结提交/阶段/模板/本人 Gate 签审/两种摘要及新增的 `credentialId`、`trustedKeySha`。原有 V1 记录保留在数据库；历史验签必须按签署时实际载荷和算法验证，不得将其伪装成 V2。
3. 凭证主体数据和状态事件只追加；激活、暂停、撤销、替换由不同于签署人的责任人记录，并要求与凭证登记/生命周期事件对应的事务内审计。凭证状态的**最新事件**为 `activate` 且签署时位于有效期内，才能签署新候选；撤销/替换是不可逆终态。普通 `transaction_timestamp()` 是数据库观察时间，**不是可信第三方时间戳**。
4. Gate Candidate INSERT 被数据库触发器再次检查签署人、公钥原字节、公钥指纹、用途、有效期和最新状态。候选、审计、outbox 在同一个 SERIALIZABLE 事务提交，三者绑定相同的凭证 ID；签署凭证状态的变化不修改历史候选/历史公钥，也不能自动赋予正式批准权限。
5. 所有凭证当前强制 `trial_only=true`，没有签发、撤销或“正式授权”的公共 HTTP 入口。数据库内部测试凭证的 `authorization_ref` 是试点关联信息，不代表公司授权；应用管理员不因管理员身份自动有密钥登记、业务审核或 Stage 签署权限。

## 生命周期与范围

| 操作 | 前置 | 后继 | 留存 |
|---|---|---|---|
| 登记 | 有独立登记人、签署人、公钥、目的、有效期、试点来源及审计 | 未激活 | 不可变凭证事实 |
| 激活 | 责任人不是签署人，审计同事务存在 | active | 追加事件 |
| 暂停 | 当前 active | suspended | 追加事件 |
| 恢复 | 当前 suspended，独立责任人审核 | active | 追加事件 |
| 撤销、替换 | 当前 active/suspended | 终态，无恢复 | 追加事件；历史验签保留 |
| 到期 | 数据库时间达到 `expires_at` | 不可新签署 | 有效期不可变；旧签名保留 |

不允许跨不同签署人复用同一个 Ed25519 公钥身份；公钥 SHA-256 唯一。替换后的新密钥必须注册为新凭证，先前签名仍由原冻结公钥独立验证。实际企业密钥保管、HSM、CA 信任链、失权通知、可信时间戳、签名意识及企业 SOP 仍属 **NO-GO**。

## 回归和发布门禁

测试必须在 `10.144.144.1` 隔离 PostgreSQL 17 新库执行完整迁移、二次 checksum、Go 集成和 OpenAPI/前端门禁；绝不能触碰正式业务数据库、生产端口 8091 或正在运行的主工作树。原测试扩大为：仅全局信任公钥而无凭证拒绝；真实登记/激活与真实 Ed25519 签署；候选精确凭证关联；未审计的生命周期伪造拒绝；撤销后新 challenge 拒绝；已签历史公钥验签仍成功；终态不得恢复。

如果当前环境未运行相关命令，本文件的验收状态保持 **NOT_RUN**，不得以代码提交代替证据。
