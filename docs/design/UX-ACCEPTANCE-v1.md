## 1. 审计级别、证据与基线

### 1.1 优先级定义
- **P0 / G0–G3 阻断**：错误可能改变数据完整性，或桌面工作台的核心交互无法完成。不得宣称桌面版 UI 已完成。
- **P1 / G4 阻断**：主业务能力已存在但 UI 操作链未闭合，或普遍出现可访问性/一致性问题。
- **P2 / G5 优化**：视觉细节、辅助信息、低频导航与非首期的可选增强；仍需记录结果。
- 与之并列的安全/版本/审核合规门禁始终生效；UX 通过不能替代既有 S/DO/MC/RB/AG 门禁。

### 1.2 证据类型
- **S**（static）：具体文件、行号、commit SHA 的静态代码检查。
- **B**（browser）：实际远端浏览器操作录屏/截图、DOM/可访问树与事件断言。
- **A**（API）：真实接口请求/响应（脱敏）、状态码、错误码、requestId。
- **D**（database/audit）：服务端事务、版本、审计记录的一致性检查。
- **P**（performance）：固定客户端、固定数据集的 p50/p95、CPU/主线程/内存记录。
- **C**（contract）：OpenAPI 与 SPEC/设计合同一致性。

每条验收至少注明：`ID / 状态 / commit / 环境 / 角色 / 视口 / 前置数据 / 操作步骤 / 期望断言 / 证据路径 / 复测时间`。不可只写“页面看起来正常”。

### 1.3 测试环境和最小数据
- 唯一运行验证：`192.168.1.22`，不可达时 `10.144.144.1`，repo `/root/repository77/filesmanage-v21`，开发 Web 端口 `18091`；**8091 不动**。
- 本地工作副本仅审阅/编辑；不跑 `npm`/`go`/浏览器 E2E，不启动服务。`AGENTS.md` 约定的 git pull/commit/push/远端执行流程仍有效。
- 用户：系统管理员、普通有权限用户、仅有 list/preview 的只读用户、无权限用户、拥有锁的用户、不同部门/组成员。使用可销毁的测试账号；不得在客户真实数据上测试删除、重命名或移动。
- 资源：纯文本 UTF-8/LF、CRLF/BOM、截断边界文本、DOCX、STEP/IGES、STL、DXF、长中文文件名、特殊字符文件名、深目录与同名目录、带审批/锁/共享失效的资源。
- 性能数据：正式压力规模为主 SPEC 的约 10k 目录/100k 文件/400k 版本；有权限的隔离数据集与专用/获批准的压力环境，勿直接在共享生产数据上压测。
- 浏览器：固定 Chromium 版本与缩放比 100%，必要时复核 Safari/WebKit 差异；截图含 1366×768、1440×900、1920×1080。
