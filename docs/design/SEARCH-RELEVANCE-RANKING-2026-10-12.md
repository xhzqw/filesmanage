# 搜索最佳匹配排序与“秒搜”性能门禁（2026-10-12）

## 本批目标

默认展示**最佳匹配**：文件名完全等于关键词（等级 0）优先，文件名包含关键词（等级 1）其次，仅索引正文命中（等级 2）再次。各等级内部按修改时间倒序，同时间以文件 ID 降序作稳定排序。用户仍可主动使用最近修改、名称升序、大小降序；无关键词时相关性等价于按时间排序。输入即搜保留 180ms 防抖、旧请求取消和按授权访问的服务端分页。

## 架构与实现

- 文件预览与业务文件列表不额外存储搜索评分。PostgreSQL 查询为搜索结果返回仅限内部的 `SearchRank`，HTTP 文件 `filePayload` 不暴露搜索排名分数。
- 相关性分页采用 `(等级 ASC, updated_at DESC, id DESC)` 组合排序。分页游标包含等级、时间、ID，必须完整解码；无效或跨排序格式游标返回第一页。服务器对每页重新应用原有 ACL/范围与高级筛选，结果总数不随分页游标减少。
- 第一轮 naive CASE 排序虽然正确，但在 100,466 文件中广泛匹配“文件”等关键词需对大量行排序，首次 HTTP 达 1371ms。已纠正为**宽词逐级限量读取**：按等级 0/1/2 分别从原索引下取 `limit+1` 总预算内的稳定有序小页，页满立即停止，不要求对 10 万行做全局动态排序。少量候选沿用 pg_trgm/Han-bigram/全文 GIN 的并集与排序，不改变准确性。
- 迁移 `0027_search_exact_name_rank.sql` 增加有效文件 `lower(name)` B-tree 表达式索引，加速大小写无关的名称精确匹配；不引入异步搜索服务或搜索数据复制。
- 前端 RareSelect 增加默认“最佳匹配”，保留最近修改、名称升序、大小降序；已保存搜索预设接受新增 sort 枚举。
- Go in-memory 存储实现相同的排序与游标规则，单测 `TestSearchRelevanceRanksAndStableKeysets` 覆盖精确/名称/正文三等级、相同时间戳和分页去重；`TestRelevanceCursorRejectsMalformedInput` 验证游标边界。

## 真实规模性能（仅独立 filesmanage_perf 数据库）

数据库包含 100,466 个文件、402,638 个版本、10,001 个目录，受控回环 HTTP 服务 127.0.0.1:18094，压测结束已关闭。均为**单次首次请求**，不是 p95 / SLA；重复访问可命中服务端短期缓存。

| 关键词 | 首轮 naive 动态排序 | 本批最终限量读取 |
|---|---:|---:|
| 文件（1000+） | 1371.0ms | 476.0ms |
| pf_ord（1000+） | 654.1ms | 251.2ms |
| 预算（1000+） | 1157.1ms | 384.2ms |
| 导出（10） | 15.5ms | 10.5ms |
| pf_bulk_9627（8） | 28.1ms | 29.3ms |

完整 Chrome 实际输入到结果可见：`pf_bulk_9627` 283ms、`导出` 275ms、`预算` 788ms、`文件` 724ms、无匹配 312ms。含 React 180ms 防抖、服务端、回环 HTTP 和渲染、自动化轮询。该设备与固定语料的样本低于 1s，不宣称所有网络/用户/负载均在 1s 内。

## 真实业务数据正确性

在专用 QA 库 filesmanage_ux_test、18092 的实际 API 与 Chrome 验证：同一关键词新建 7 个文件，文件名精确匹配是最早写入，正文命中最新写入。使用 2 条/页服务端 cursor 连续取 4 页，结果等级严格 `0,1,1,1,2,2,2`，7 个 ID 各出现一次，总数每页均为 7。主动切换 `updated_desc` 时，最新的正文文件恢复为第一批结果。真实浏览器保留 WF-30 50→60 搜索分页、输入自动搜索与目录/上传回归。

## 尚未验收的边界

- 公网或高 RTT、多人复杂授权、100/200 并发及长时间稳态 p95/p99 搜索 SLO。
- 跨设备并发重命名期间的分页结果集快照一致性（游标按查询当时排序键，而非数据库版本快照）。
- 对复杂中文复合查询的语言学相关性、拼写纠错及同义词召回（本批刻意不改变命中语义）。
