# G2 文件工作台 · 第五批断点上传与真实规模验收（2026-10-11）

## 本批整改

1. **客户端与服务端恢复窗口统一**：原客户端 48h 元数据缓存与 Go 服务端初始 24h 会话期限不一致。现在按原始入队时间严格保存最多 24h 的浏览器恢复提示，不因任务进度刷新而自动延长期限；服务端接收分块可独立延长自己的会话有效期。
2. **单一幂等身份**：移除 `web/src/shared/resumableUpload.ts` 中按文件派生、无用户作用域的独立 localStorage key。恢复操作只使用 `uploadStore` 用户隔离任务和指纹校验后保存的 `idempotencyKey`，避免不同账号/会话串用第二份凭据。
3. **网络中断对账**：PATCH 响应丢失时先查询服务器已接收偏移量，已接收就跳过重传；完成响应丢失时先查 durable session，若 `committed` 且有 `result`，直接返回服务器已提交结果；若仍 `open` 且已收齐，则使用同一会话完成请求再试一次。异常偏移立即拒绝，过期/取消会话不自动创建新的上传。
4. **错误文案**：网络未知结果提示先进行原任务幂等核对；服务端会话失效时提示核查目录后再处理，不承诺不确定的提交成功或失败。
5. **自动验收**：`scripts/ux_resumable_reconcile_check.mjs` 测试客户端实际 TS 上传模块的丢失分块响应、丢失提交响应、已提交重放、非法偏移、过期会话和完成重试；挂入远端 `scripts/build.sh --with-tests`。另在隔离 `ux_workflows_check` 添加不同认证会话同一上传 ID/偏移接续、重复块 409 和最终唯一文件/版本断言。
