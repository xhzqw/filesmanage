# CDW G18：审批链审计包、通知人工督办与技术闭环

G18 沿用 G2–G17 的正式审批、专项岗位任命、文件 ACL 和已有通知记录。所有新功能均为受控操作或读取，不替代外部法规解释、受控发行或正式批准。

## 数据与权限边界

1. 文控审计下载 `GET /api/workbench/qms-formal-lineage/{id}/audit` 返回服务端生成的 JSON 快照，内含审计时刻、请求文控 ID、完整有界的审批链（每次冻结 SHA、审批模板、制度版号、签批状态）、**所有审批节点（含未签、跳过节点及强制节点属性）**、每次签署的真实身份/理由/授权快照、逐人通知/阅读确认/人工督办记录，以及分离的闭环计数。仅当前具有 `document_control` 角色且可以实时预览相关文件的用户能够导出。返回 `X-Content-SHA256` 以便校验文件字节，`Cache-Control: no-store`。记录的是**导出请求**而非宣称客户端已下载成功。超过 G17 31 节点显示限制的链路，包含**祖先方向**超过上限的场景，均不能导出伪装成完整证据的部分文件。
2. 数据库迁移 `0068` 增加**人工一次性督办事实**。督办仅可针对某人尚未阅读的原有中断通知发起，记录督办人、具体收件人、原审批 ID、时间和不小于 16 字的客观说明。服务端事务重新验证文控角色和源文件 ACL；DB trigger 也检查角色、收件人不是自己、通知未读、审批关联准确。唯一索引禁止针对同一通知不断制造多个督办事实，记录不可 UPDATE/DELETE，相关原通知仍由本人独立确认。
3. 文控原工作台提供最多 100 条当前权限范围内的收件名单、未读情况与人工督办入口。原收件人仍在个人通知视图收到提醒内容；系统不擅自向邮箱/SMS 推送，也不声称收件人实际已查看。没有经正式批准的 SLA、时限或上级角色时，页面不出现“违法逾期”或自动升级结论。
4. 原审批追溯面板呈现按**当前链条**计算的中断次数、重启次数、未确认收件数、最终审批状态；“审批批准”和“全部通知已读”分属两条责任，不把这组统计冒充企业全覆盖质量 KPI。也不将批准候选版本当作正式生效发行。
5. G18 验收必须通过隔离空 PostgreSQL 实际 70 项迁移和 G2–G18 全链，包括越权督办、重复督办、已读后督办、审计包源事实一致、真实前端构建/Go/OpenAPI/架构、Chrome 1440/1024/780。验收通过后仅更新 18091 开发库，绝不触碰 8091 及现有用户未提交文件。

## 后续限制

本期统计准确对应用户正在看的**单条审批链**，不是全公司的 CAPA 关闭率或质量管理绩效。督办是内部持久可审计记录，并不向客户、邮箱或短信系统发送提醒；自动升级需要正式制度提供角色、期限及合法渠道。超过 31 个审批实例的异常长链，本期拒绝输出不完整“全量审计”，后续应建设分段连续性校验证据。
