# CDW QMS 任命撤销、收件人通知、精确受控证据与 DHF/DMR 门禁

本文件是开发及验收记录，不是已经发行的企业质量制度。

## 不变量

1. 原任命只能由有该文件实时文控权限、且不是被任命人或提报人的人员撤销。只允许 `verified → revoked`，有明确撤销理由和时间。历史任命原件、独立核验记录、先前审批签字永不被覆盖；撤销状态不可逆，重新任命须重新建记录。
2. 当前签批资格始终实时校验 `status=verified`，岗位节点、文件范围、有效期和制度/任命凭据的**当前生效受控发行版本**。撤销后不允许待执行的 QMS 签署，数据库直接写签署也无法绕过。
3. 撤销同一事务写入目标收件人的 `cdw_qms_appointment_alerts`（被任命者、提报者、原核验人和受影响待签节点）。既有 CDW 领域事件及 outbox 同步写入，但不能把 outbox 入队自动算作真实已读。收件人登录后在「任命核验」查看，明确点击「已知悉」才记录阅读时间。
4. `GET /api/workbench/qms-appointments/:id/evidence` 通过任命证据的唯一发行 ID 查找有效指针，校验批准发行的、已分发的固定 DOCX 制品 SHA-256、Blob 状态和长度；还必须同时通过目标文件、任命制度文件及凭据源文件的 ACL，以及本人实时文控权限。输出明确的制品 SHA 头和不可缓存正文，绝不以文件普通最新预览替代。
5. `ZS-QP-09` 委托的 DHF/DMR **专属签批规定**没有权威有效文件时，不允许通用 QMS 模板推定法定签批资格。识别文件名 DHF/DMR、设计历史文档、器械主文档及既有文档类别；正式发起及签署均实行应用层+数据库双门禁。技术起草、归档、准备评审继续允许。
6. 「任命核验」工作台对有相应文控权限且无利益冲突的非管理员同时展示待审核和已核验任命，后者可在同一任务详情提交撤销。精确凭据请求写入安全审计的 `content.requested` 事件（不冒充已完成传输）；前端不再回退普通最新预览。

## 业务限制

- 当前实现**不**自动判定任命书真伪或实体法规资格；上面的文件类别识别并不能涵盖每一种非标准命名，文控登记及人工审核继续必要。
- 专属 DHF/DMR 正式流程真正解锁前，仍须真实公司按照原程序批准单独权限矩阵；禁止在测试和开发环境生成伪造的岗位任命或“合规审批”。
- 当前“通知”是系统内持久收件人通知，不声称已通过短信/邮件外发；通知是否已读必须有收件人真实动作。
- 如果精确发行制品尚未真正生效、已撤回、未实际分发或 Blob 不一致，下载将失败关闭，不能退回普通最新文件。
- 原始 `docs/流程参考文档/` 不参与改写，8091 生产入口不在本次部署授权范围。
