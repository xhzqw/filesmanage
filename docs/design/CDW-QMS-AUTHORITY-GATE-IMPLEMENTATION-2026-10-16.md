# CDW QMS 授权依据门禁：工程增量记录

状态：**工程验证材料，非公司受控制度**。参照 `CDW-QMS-GENERIC-PROVISIONAL-RULES-v0.1.md`。

## 本次实施的边界

已有 CDW 工作台的普通审批流程保留兼容。质量体系正式审批使用保留模板前缀 `qms_` 或 `cdw_qms_`，新增：

- `authorityBasisReleaseId`：正式审批模板发布、审批人授予文件级角色的可选入参。对 QMS 模板此字段**必填**；普通模板仍可省略。
- 依据必须是**当前有效的 CDW 受控发行版本**，使用实际 `cdw_effective_pointers` 及发行状态双重校验；仅输入文档编号、文件名、管理员声明或本项目草案不构成有效依据。
- QMS 审批开始、每次签署都重新核验依据仍有效，且指定审批人的当前授权必须绑定同一发行版本。审批轨迹同时记录角色绑定 ID 和制度发行 ID。
- QMS 正式批准后，受控发行准备、正式签发及最终生效时还要重新核验制度依据；依据失效将阻断准备/签发，生效则保留有审计记录的未满足门禁结果。
- 模板保存采用现有不可变版本机制；新增字段亦不允许更改已发布模板。新 SQL 迁移中的触发器阻止绕过 API 直接发布未附有效依据的 QMS 模板。
- 审批界面允许选择“质量体系受控文件”，通过现有受控有效文件检索选择依据，缺少依据时禁用正式审批步骤。错误 `E_CD_POLICY_AUTHORITY_PENDING` 返回 409 并提供明确原因。
- 所有修改严格只增加适用门禁，不生成监管报告成功记录、DHF/DMR 官方审批链，不自动修改 ERP/WMS 或实物放行。

## 保留的合规差距

**现行有效的文件及授予了角色，不自动证明批准权限在实体制度中真实存在。** 当前新增的机制只校验“有效文件发行物 + 技术授权关联 + 真实操作者”；独立质量/文控人员对审批矩阵内容、任命/代理资格、法定报告时限的**实质核验**和相应正式授权仍需后续能力。不能把管理员选择的两个人当作已经依法任命的总经理或管理者代表。

49A 案例可先使用普通任务编制勘误材料，尚不能在缺少经核验的 `ZS-QP-01` 受控有效发行和正式签批角色矩阵时形成正式审批或发行。

## 验证清单

1. 普通 G7 审批的既有角色/模板接口兼容，无需提供新增字段。
2. 新的 `qms_` 模板：不提供依据、提供不存在的发行 ID，应返回 409；数据库直接 INSERT 无依据须受 `23514` 阻断。
3. 角色授权：提供不存在、过期、失效、已撤回的发行依据必须拒绝。
4. 开始与签署：基准受控发行被取代或撤回，不得继续制造 QMS 正式批准记录。
5. 日志和快照需包含制度依据、实际绑定及审批人，而非只记录用户输入字符串。
6. 仅在 **隔离数据库** 运行联调/反例测试，不在生产数据里伪造审批角色、签名或产品发行。

本轮不宣称用户已批准第 77–83 项规则，也不声称 49A 已实际审批。
