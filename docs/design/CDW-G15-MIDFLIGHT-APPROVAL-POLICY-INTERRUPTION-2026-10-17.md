# CDW G15：受控制度变更与进行中正式审批的冲突终止

G14 已实现专项制度生效指针变化后的影响评估，但还不能将同一变更关联到进行中审批。G15 使待审实例在源制度换版、失效，或该申请绑定的专项授权被文控撤销时自动冲突终止。规则适用于实际登记且已独立核验的 DHF/DMR 专用制度版本，不扩张到普通文件。

## 约束

1. 数据库触发器在变更事务内识别使用相同 **文件 ID + 审批模板 ID + 专项授权 ID** 的 `pending` 正式审批，按审批实例排序逐行加锁，记录原文件不可变 SHA、原模板、原发行、影响评估关联、完成签署数量、未完成节点和原因；立即将实例设为 `conflicted`，将所有 `ready/waiting` 节点改为 `skipped`，写入领域事件。已完成的签字和批注不得删除或重写。
2. 独立的状态触发器防止 `conflicted → pending`，决策与候选文件写入触发器防止直接 SQL 利用旧实例补签或创建批准候选版本；即使政策指针后来恢复，也不能把旧流程恢复为可以签署的实例。恢复需基于最新政策**重新发起新的正式审批实例**，履行原系统的分类、专用证据、岗位任命和冻结 SHA 检查。
3. G14 的影响任务可能合并同一版本的重复变更，因此 G15 除了订阅“新建影响记录”，还直接监听受控指针状态变化。即使影响记录因唯一索引合并而没有再次插入，新出现的审批实例也必须被切断。
4. 授权撤销即使没有物理版本指针变化，也必须独立触发冲突终止。原申请人、各批准参与人及文控可按权限查看；可见性同时与两个源/目标文件实时 ACL 相交。历史证据只读，不提供“继续旧实例”的界面动作。
5. 工作台使用原有「任命核验」区域显示冲突列表及原因，提示应基于有效模板重新发起；不添加另一个审批状态机。已批准的历史实例不自动撤销，仍由 G14 影响评估与相关法规程序决定后续处置。

## 验收

使用每次创建且自动销毁的隔离 PostgreSQL 空库应用全部迁移，覆盖中途换版、受控授权撤销、旧状态不可恢复、假冒候选文件被拒绝、无关实例不受影响、重复变更幂等。执行 Go/TS/Vite、OpenAPI、架构测试与 Chrome 三宽验收，只对 **18091 开发环境**应用新的迁移。未获授权前不得调整 8091，原质量文档及已有非本任务的工作树修改不触碰。

## 后续工作

G15 保留全部冲突历史，但没有假定所有历史冲突都属于未读待办。若需使每个审批申请人、签批节点收到明确的撤销/中断通知，应新增独立收件确认状态，而不是永久用全部历史行作为导航未读数量。此外，新流程的“重新发起”应保持一个新的审批实例与重新授权证据，旧实例永远不可继续。
