# WebSocket 持久实时事件通道（协议 v3）

登录用户的浏览器会使用已有 HttpOnly Session Cookie 订阅服务端通知；文件读写与权限判断仍走现有 REST API。

- HTTP 页面连接 `ws://192.168.1.22:18091/api/events/ws`。
- HTTPS 页面连接 `wss://192.168.1.22:18443/api/events/ws`。
- VPN 可使用 `10.144.144.1` 的对应端口。
- 不强制 HTTPS，不修改 `443`、`8091`；Nginx 已透传 Upgrade。
- 必须同源 Origin，包含方案、Host 与端口。服务端验证 Cookie 并拒绝未完成改密的用户。
- 不支持查询参数中的令牌，不接收客户端业务命令，连接中不包含密码、Cookie 或文件内容。

## 实时事件（协议版本 3）

| type | 含义 |
|---|---|
| `connection.ready` | 建立或恢复连接，含 `version:3`、`cursor`（十进制字符串）、`resync` 和 `heartbeatSeconds:12`；首次、越界或过期游标要求全量校准 |
| `connection.heartbeat` | 每 12 秒重验 Session |
| `session.changed` | 用户登录、退出、改密、停用或重置密码后触发，前端重新请求 `/api/me` |
| `session.revoked` | 当前 Session 已失效，前端退出到登录页 |
| `session.password_change_required` | 必须修改密码 |
| `server.unavailable` | 暂时无法检查会话，不应误判为退出 |
| `workspace.changed` | 已提交的资源或权限变更；`scopes` 是无敏感详情的模块失效提示，客户端重新请求自己有权访问的数据 |
| `approval.changed` | 仅通知对应审批参与者刷新审批与消息 |
| `state.resync` | 有界缓冲拥塞导致不同事件合并，客户端必须刷新全部可见资源、会话和通知 |

支持的 `workspace.changed.scopes`：`file`、`folder`、`trash`、`search`、`stats`、`permissions`、`collaboration`、`organization`、`review`、`lifecycle`、`approval-policy`、`presets`。浏览器会按范围合并 120 毫秒内的通知，再调用现有 HTTP 查询接口。文件列表/树、文件预览与版本、回收站、搜索和搜索预设、统计、共享与关注、组织与角色委派、审批策略、生命周期台账及策略和评论等页面按影响范围更新。个人收藏和搜索预设的变更仅发送到该用户的会话。

核心工作区通知由数据库 **事务内部**触发器写入 `realtime_events`，与业务数据一并 Commit；回滚不会留下持久通知。事件载荷不包含资源 ID、名称、正文、文件路径、账号资料或 ACL 明细。个人关注、搜索预设、会话变更、审批通知记录为对应 user_id 的私有事件，数据库回放查询只返回当前身份有资格接收的事件。所有刷新均重新走服务器权限判断、分页和版本控制，绝不将通知内容当作资源数据。

连接断开后客户端带随机抖动指数退避重连，最多约 30 秒；浏览器恢复联网立即尝试重新连接。客户端检测 40 秒无服务端消息的半开连接（含 25 秒内未能建立的连接），主动断开并重新连接；隐藏标签页暂停心跳判定，恢复可见后重新检查。每次 `connection.ready` 都请求客户端重新核对当前状态，避免断线期间丢事件。会话失效事件立即封闭客户端连接，旧身份查询结果不能将其重新激活。连接和重连不会阻止 HTTP 文件管理功能。服务端全局最多 128 条连接，入站消息不超过 1 KiB，发送超时为 4 秒；每个订阅通道是一条有界缓冲：同类型的工作区事件合并去重范围，不同类型的通知合并为 `state.resync`，该标记在拥塞期间持续保留而不是被后续消息覆盖。

缓存一致性：每次已提交的资源变更使搜索和统计缓存修订号递增；查询开始时获取的缓存修订号必须与填充时的修订号一致，否则只返回该请求本身的数据，**不得把旧数据库读取结果写回缓存**。这关闭了旧查询在缓存失效后迟到并重新污染缓存的竞争窗口。只影响审批策略等元数据的通知不清空昂贵的统计缓存。

## PostgreSQL 持久化、跨实例与游标

- 迁移 `0028_durable_realtime_events.sql` 创建 `realtime_events`：保存 `id`、`user_id`（可空）、`event_type`、匿名 `scopes` 和时间。核心业务表的 statement-level 触发器在原事务内追加事件；个人变化使用 user-scoped 行级触发器。事务级 advisory lock 确保序号的已提交顺序不逆转。该机制不能用“提交后发一条内存消息”替代。
- 任意实例共用相同 PostgreSQL 事件日志，WebSocket 按 `id > cursor` 读取，每次最多 128 条，连接最多每 2 秒查询一次；本实例内存事件可提前唤醒读取，但不再作为持久消息来源。即使后台通知或 `pg_notify` 丢失，轮询仍能补发。服务端缺少日志表时拒绝启动，不允许静默降级。
- 迁移 `0030_realtime_skip_empty_mutations.sql` 使用 INSERT/UPDATE/DELETE 的 transition tables 过滤 **影响 0 行**的数据库语句。CAD worker 每 3 秒执行一次无任务轮询，不再产生假的 `workspace.changed:file` 通知；真实批量操作仍按语句合并为一个持久事件。前端只刷新受影响的数据：文件内容更新不重新加载目录树，已有文件行及预览在重新校验过程中保持可见，失败鉴权则立即移除受限预览。
- 浏览器在 **每个标签页的 sessionStorage** 内按当前用户独立保存 `fm-live-cursor-v3:<userID>` 书签（不是凭据）。不能存入共享 localStorage：一个已同步的标签页不能替另一个未同步标签页确认游标。刷新当前标签页仍保留断点；新标签页在首次连接时全量重读。重连通过 `?cursor=<数字>` 恢复。服务端只对认证身份返回公共和该用户的私有事件。浏览器发出本地刷新提示后才前进书签，因此是可重复的 **at-least-once** 提示语义；后续 REST 读取仍有自己的失败重试机制。旧 v2 没有书签，升级时会先全量校准。
- 首次接入、非法/未来书签、已超出保留期等情况返回 `connection.ready.resync:true` 并提供最新游标，浏览器全量读取现有有权访问的数据；不会假装可以逐条重放已清理的事件。迁移 `0029_realtime_replay_indexes.sql` 引入持久清理水位，即使事件表已经被清空也可以检测断档；长连接每个心跳周期都会核对水位，必要时发送 `state.resync`。
- PostgreSQL 对公共事件和 `(user_id,id)` 私有事件建专用索引；单个用户的查询无需扫描其他用户的大量通知。实例级消费者使用独立的内部事件流（有用户 ID、不可通过 WebSocket 暴露），用于在**另一实例撤销会话**时清理本实例会话缓存，并在数据库中断恢复或事件被清理时整实例失效缓存。单实例消费者因启动时数据库短暂不可用不会永久停止。
- 默认保留 90 天（每日最多清理 5000 条），远端配置 `FILESMANAGE_REALTIME_RETENTION_DAYS=0` 禁止自动清理，其余允许 1–36500。文件版本、审批记录、业务审计仍由各自的持久表负责，此处持久化的是匿名变更通知，不是协同文字操作日志或文档内容。
- 运维先执行远端 `go run ./cmd/migrate -dir migrations` 完成 0028，再编译与重启。检查日志可使用 `SELECT count(*),min(id),max(id) FROM realtime_events`。该表带用户 ID，数据库权限应与其他业务表同级管理。

需要注意：跨实例一致性依赖事件轮询（约 2 秒），并非数据库提交完成的同一瞬间所有实例缓存即更新；敏感权限判断仍以服务器授权验证为准。应用进程即使没有 WebSocket 连接也会运行内部事件消费者。

## 验收

仅在远端 `/root/repository77/filesmanage-v21` 执行 `bash scripts/build.sh --with-tests`，验证跨站拒绝、无 Session 拒绝、合法握手返回 101、v3 游标重放、断档校准、用户专属通知隔离和双入口 WS/WSS。数据库测试必须覆盖事务回滚不产生已提交事件、两条独立连接按游标读取同一日志，以及并发事务顺序。文件、目录、权限、审批的变更应在事务提交后可读，失败事务不可读；失权时旧预览不得继续显示受限内容。
