# 文档管理系统全局审计与整改路线图

> 日期：2026-10-10；基线：`aa6b5ed`（本报告针对修复“关注状态”前的主分支做静态审计）。
> 方法：检查前端页面/服务接口/数据库适配层/主要业务逻辑、现有验收文档与测试门禁；并核对用户实际截图。**并非全面动态安全测试或生产压力/灾备演练**。
> 分类：**确认现存问题**／**按文档管理产品定位应补能力**／**外部条件与上线门禁**。不以“接口存在”替代真实使用体验或正式上线验收。

## 1. 综合判断

当前系统已具备一个内部文档管理系统的**基础业务闭环**，不是只有文件浏览器：文件/文件夹操作、上传及去重、历史版本/不可变回滚、回收站及恢复、角色/工作组/目录授权、有效权限解释、审批与文件锁、DOCX 在线编辑、PDF/图片/视频/文本预览、部分 CAD 及多格式预览、内部共享与关注、全文搜索、统计与 CSV、基础审计、WebSocket 与会话管理均有实现。对应证据参见 `internal/httpx/router.go:95-177`、`docs/ACCEPTANCE-MATRIX.md`、`docs/RELEASE-GATES.md`、`web/src/pages/Preview.tsx`。

但**不能据此声称企业级 DMS 已完成**：既有 SPEC v2.1 验收矩阵为 123 PASS / 2 PARTIAL / 1 EXTERNAL；UX 单独验收矩阵本身标注“不自动继承已有 PASS”，且现场截图反复发现布局/状态问题。按代码确认的产品能力缺口包括缺少元数据/标签体系、扫描件 OCR、文档保留/冻结策略、跨版本内容对比；同时存在列表硬上限和文件选择器无法遍历全部数据。生产环境尚未获授权，上线级一致性备份未闭环。

## 3. 发现与整改建议（按优先级）

### P0 — 正式投产阻断；不等于当前开发服务已经发生故障

**O-01 备份数据一致性与恢复目标未闭环。** `docs/M8-BACKUP-AND-SERVICE-READINESS.md:31,92` 明确记录 DB 快照与对象文件存储快照在并发写入下可能非同一时间点，生产 RPO/RTO 未证明。方案：制定可恢复的一致性点（写屏障、媒体 generation/manifest 事务化方案之一），实现带校验和的快照与恢复，建立周期性演练，形成带 RPO/RTO 证据的恢复报告。验收：并发上传/版本写入场景，备份恢复后的元数据—blob 哈希/引用一致，真实定时任务和告警覆盖。

**O-02 上线批准和服务守护尚未完成。** `docs/RELEASE-GATES.md` 与 `docs/OPEN-BLOCKERS.md` 标注正式环境 NO-GO、systemd 未安装、生产 8091 未授权。不要擅自切换生产端口。方案：生产配置隔离、监控/告警、升级/回退与安全验收签收后再申请上线授权。

### P1 — 使用规模、核心操作体验及维护成本问题

**UX-01 状态可读性与统一组件。** 截图及 `CollaborationPanel.tsx:318` 原代码证实“正常/已删除或不可访问”为裸字符串；本批使用 `RareBadge` + success/danger + 状态文字。下一步把审批、锁、会话、分享、回收站等页面的状态字段统一映射到 RareUI 语义 token，禁止只靠颜色表达。

**UX-02 失效资源仍为可点击链接。** `CollaborationPanel.tsx:314` 不检查 `f.unavailable` 就生成 Preview/目录链接，而“分享”按钮会禁用。建议失效资源保留资源名和取消关注操作，但不继续生成会失败的导航；不在无权限时透出原始敏感路径和原因。

**DATA-01 关注/分享列表分页缺失（已确认）。** PostgreSQL 对关注 `LIMIT 500`、发出/收到分享 `LIMIT 200`；`collaborationApi.favorites()/shares()` 均无 `cursor/limit`。超过上限的旧记录无法翻页，当前结果数量会被误认为总数。需要服务端稳定排序的游标 API + `hasMore/nextCursor`，客户端增量加载、过滤、空态和上限提示。验收：>500 关注、>200 分享，含新增/删除/并发写入、失权记录无重复或遗漏。

**DATA-02 新建分享/关注时资源选择不完整（已确认）。** `CollaborationPanel.tsx:13,132,263-286` 仅前 100 个目录候选；文件模式调用 `folderFiles(...limit=50)` 并且无加载更多。即使服务端有第 51 个文件，页面也不能选择它。建议统一 `FolderPicker` / 分页资源列表，按授权范围搜索 + 游标，不再自行维护全量树后 `slice`；同时保留键盘选择/焦点和历史路径。

**UX-03 名称、状态与空态缺少跨页面规范。** 代码中 `CollaborationPanel` 使用“关注”，`Preview.tsx:111` 使用“收藏”。组织管理已有 `RareBadge`，分享和其他列表却重复字符串。定义单一文案/状态枚举、范围/继承展示和错误态规范，检查所有页面实际截图及窄区布局，维护视觉回归数据集。

**FILE-01 大文件上传的断点续传与恢复能力不足（架构升级建议）。** 目前队列单并发，单文件走一次 multipart 请求；后端单次请求 1 GiB。一次网络中断通常需要重试完整文件，不具备分块上传、续传、跨会话恢复与服务端分块完整性确认。机械模型/局域网大文件工作流值得列入 P1，但先评估真实文件大小与网络条件，再确定实现方式。

**AUD-01 审计视图尚非文档全生命周期记录。** `PermissionInsights.tsx` 主视图是 ACL/组织/分享权限变更；文件预览、下载、导出、版本回滚、审批、移动、删除/恢复应按资源、操作者、时间、事件、结果、请求追踪做统一查询与导出，需在脱敏和授权前提下实现。已有基础 audit 记录，应先核查覆盖率/审计表实际事件，再补接口，不应另造孤立日志系统。

**UX-04 原设计验收不能直接视为完成。** `docs/design/UX-ACCEPTANCE-v1.md` 明确要求同版本远端视觉证据。必须建立正常、加载中、空结果、无权限、超长文件名、失效文件、窄侧栏及弹窗顶部层级的多尺寸回归，特别覆盖状态标签、对齐、表格截断和滚动归属。

### P2 — 从内部文件管理升级为成熟 DMS 的能力建设

**DMS-01 文档分类与业务元数据。** 现有 `FileItem` 主要是文件名、目录、大小、内容类型、哈希、上传人、版本和时间；当前未发现标签、业务分类、可配置字段/模板及元数据筛选 API。应设计部门/项目/文档类型（图纸/合同/SOP/检验记录）元数据 schema、权限与变更历史，优先少量刚性字段而非自由字段泛滥。

**DMS-02 PDF/扫描件 OCR 与全文搜索覆盖。** `ExtractText` 明确只提取纯文本/DOCX，PDF/图像/CAD 只贡献文件名；1 MiB 内容上限和 best-effort 的索引失败可造成“有文件但搜不到正文”。应引入异步索引任务状态、可诊断失败/重试及限额，PDF 文本层提取先于 OCR，OCR 应有语言、成本、保密和不可信文档隔离策略。

**DMS-03 文档保管期限、合规冻结和销毁控制。** 现有回收站和永久删除不等于可审核的保留策略/Legal Hold。建议基于文档类别配置期限、到期告警、冻结不可删除、销毁批准与审计。没有明确法规/业务场景前不应随意自动删除。

**DMS-04 版本差异比较与审查批注。** 当前版本列表可以回滚但不能直观看两版文本/字段变化；建议先做纯文本双栏 diff、版本摘要与审查备注，再评估 Office / 图纸差异和预览标注，复用现有不可变版本，不修改源文件。

**DMS-05 更成熟的审批编排。** 当前目录审批策略核心是指定一名审批人+是否启用。可在有业务场景后设计多节点顺序/并行审批、代理/超时、按文件分类触发和审批报告；先明确工作流语义、幂等和历史策略不可变性再扩展。

**DMS-06 产品级导航与跨域组合体验。** 搜索结果到文件定位、关注失效的后续操作、批量操作反馈、更多菜单、统计区间与组织信息可共享统一资源 Inspector、状态枚举与反馈规范；减少在每个页面重复各写一套筛选器/表格。

### 外部条件

**EXT-01 DWG 原生预览许可。** `OPEN-BLOCKERS.md BLK-03`：需客户决定是否采购许可/SDK；不能默认为已支持。保留现有 DXF 与明确降级说明。

**EXT-02 容量与性能基线。** `RELEASE-GATES.md` 记载 10/100 并发通过、200 并发仅 10/11；此结果来自共享主机，不能宣称已完成独立生产容量认证。应在约定部署资源上重测并给出容量阈值、告警和扩容预案。

## 5. 审计结论与边界

- **目前最优先的不是重写架构，而是修复数据完整可见性和跨页面行为一致性。** 已有权限、版本和文件功能不应推倒重做。
- 基础规范的 PASS 只说明原 SPEC 已声明功能的既有证据，**不代表扩展 DMS 能力已具备，更不代表新 UI 已视觉签收**。
- 本报告没有对生产数据做修改，也没有尝试未授权安全测试。问题分级是按业务影响和代码证据判断，涉及法规、审批多级与文档生命周期的能力需用户确认具体需求。
